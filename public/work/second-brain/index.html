THE PROBLEM

A real starting point.

Notes become less useful when they are trapped in one application or disconnected from the work they support. I wanted a knowledge workspace that starts with ownership of the files themselves.

THE APPROACH

Make the relationships clear.

The canonical record is a local Markdown vault with structured metadata. A database index supports discovery and can be rebuilt from those files. Objects have stable identities so their relationships can survive changes in title or location.

DESIGN DECISIONS

01

Files before databases

The vault writer is the persistence boundary. SQLite is an index, not the only copy of a thought.

02

A shared object model

Notes and other knowledge objects use stable identifiers and structured links, making a graph view possible without changing the original files.

03

Offline comes first

Android and local storage shape the architecture. AI and graph capabilities are enhancements around the personal workspace.

Where it stands

The project state records graph work in progress and Android storage-access verification still to complete. This is a prototype, not a published app-store release.

Source basis: Reviewed project state, feature documentation, vault writer, graph provider and link schema.
