THE PROBLEM

A real starting point.

A tuition administrator needs a clear view of students, attendance and fees without having to operate a spreadsheet directly. Mistakes must be correctable, and corrections must not quietly overwrite someone else’s work.

THE APPROACH

Make the relationships clear.

The website acts as the everyday workspace while Google Sheets remains the record of authority. Server functions validate changes, and correction flows carry a reason and the version the user originally opened.

DESIGN DECISIONS

01

A visible record of corrections

Attendance and payment correction endpoints keep the editing process separate from simply recording a new entry.

02

Protect against stale changes

Version-aware corrections reject an edit when its source record has changed. The user can reload before trying again.

03

An administrator’s view

Student profiles, reports and history bring the underlying records into the website so routine work does not require opening the Sheet.

Where it stands

The repository still contains a development authentication path. Production Google identity and access configuration must be completed and validated before a client launch.

Source basis: Reviewed attendance correction and report endpoints, Sheets integration, student profile components and the application shell.
