CASE STUDY / 03

SECOND BRAIN

An Android-first knowledge system designed to turn PDFs, images, URLs and text into structured, interconnected Markdown notes inside an Obsidian vault.

ROLE

Creator · Product Strategist

TARGET

Android · Galaxy S23

MODEL

Five inputs · one shared pipeline

OUTPUT

Interconnected Obsidian Markdown

01 / OBJECTIVE

Capture is easy. Useful connection is the hard part.

The project specification defines a zero-cost knowledge pipeline that accepts PDFs, text-based images, URLs, raw text and text files. Every route converges into one processing pipeline, then outputs structured Markdown rather than creating separate workflows for every input type.

One pipeline

Input detection changes the front door, not the downstream processing contract.

Real semantic links

Related notes are selected from vector embeddings and cosine similarity instead of guessed relationships.

02 / ARCHITECTURE

Ingest → reason → link → vault.

The documented system separates ingestion, processing, linking, vault output and self-healing. A shared Note object acts as the contract between backend pipeline work and the mobile renderer, reducing integration ambiguity.

03 / PRODUCT DECISIONS

Prove the risky seam first.

  • 01The specification makes vault-write reliability the first gate: prove a long note can reach a real Obsidian vault before investing in complex interface work.
  • 02Android Storage Access Framework is the primary write path, with URI and Share Sheet fallbacks.
  • 03Each finished note is embedded once and stored locally; the design explicitly avoids re-embedding the entire vault.
  • 04Raw extracted input is preserved locally while embeddings remain out of the Markdown file.
  • 05The Doctor layer is constrained to payload/connectivity repair and is explicitly forbidden from modifying application source code.

SOURCE OF TRUTH: verified against the active private Second Brain repository and its current project specification. The architecture is presented as documented product design; this page does not claim every roadmap item is already shipped.

04 / SYSTEM PRINCIPLE

Build the knowledge seam, not another notes screen.

The product’s differentiator is the relationship layer: ingestion is only valuable if information can be normalized, structured, connected and reliably written back to the user’s existing knowledge environment.
